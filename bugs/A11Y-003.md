# A11Y-003: Campos dos modais de login e de contato sem rótulo

| Campo | Valor |
|---|---|
| Impacto (axe-core) | Crítico |
| Prioridade | Alta |
| Status | Aberto |
| Critério WCAG | 4.1.2 Nome, função, valor (nível A) |
| Regra do axe | [label](https://dequeuniversity.com/rules/axe/4.14/label) |
| Telas afetadas | Modal de login (2 campos) e modal de contato (1 campo) |
| Ambiente | demoblaze.com, Chrome, auditoria automática (AC-04 e AC-06) |

## Passos para reproduzir

1. Na página inicial, clicar em **Log in** com um leitor de tela (NVDA) ligado, ou rodar `npm run test:a11y`.
2. Navegar até o campo de usuário com a tecla `Tab`.
3. Repetir no modal **Contact**, no campo de e-mail.

## Resultado esperado

Ao chegar em cada campo, o leitor de tela anuncia o que deve ser digitado, por exemplo "Username, caixa de edição".

## Resultado obtido

O axe encontrou campos sem rótulo associado:

- Modal de login: 2 campos (exemplo: `#loginusername`).
- Modal de contato: 1 campo (`#recipient-email`).

O leitor de tela anuncia só "caixa de edição", e a pessoa não sabe se deve digitar o usuário, a senha ou o e-mail.

Observação: o **modal de cadastro**, que tem os mesmos campos de usuário e senha, não apresentou essa violação. Isso indica que o problema está na forma como os rótulos foram ligados aos campos nesses dois modais, e não no layout.

## Sugestão de correção

Ligar cada texto de rótulo ao campo com `<label for="id-do-campo">`, como no modal de cadastro. Se o rótulo não puder ficar visível, usar `aria-label`.
